# 分析包来源路径防覆盖保护设计

## 问题

分析包迁移后，若用新的 `EVCS_PROJECT_ROOT` 重建清单，当前查找根目录可能覆盖清单中记录的原始来源路径。这样会把“来源在哪里”和“这次到哪里查找”混成一个字段；即使指标和输入哈希未变，溯源记录也会失真。

## 保护规则

1. 首次审定来源时，生成只初始化一次的 `source-provenance.lock.json`，按包内相对输入路径记录冻结清单中的原始 `source_path`、`source_archive`、`source_member` 字符串、冻结包内路径、预期SHA-256及冻结清单哈希。来源字符串逐字保留；迁移所需的仓库相对定位提示另记为 `lookup_path_hint` 和 `lookup_archive_hint`。已有锁文件时，普通清单重建不得覆盖它。
2. `manifest.json` 中的 `source_path`、`source_archive`、`source_member` 始终从来源锁读取；本次解析到的位置另记为 `lookup_path`、`lookup_archive` 和 `lookup_root`。查找目录改变只改变 `lookup_*`，不能改写 `source_*`。
3. 已有 `manifest.json` 且锁的来源字符串需要从冻结记录恢复时，只能显式传入与锁定SHA-256相符的冻结来源清单；同时逐项核验旧manifest、锁和冻结清单的输入项及内容哈希。普通重建不得执行来源字段校正。若manifest和锁均不存在，首次建包须明确给出来源清单，避免把迁移目录误登记为原始来源。
4. 若原始来源不可达或哈希不匹配，工具保留来源字段、标记查找失败并以非零状态退出；不得把“找不到”改写成“源端没有数据”。

## 最小迁移验收

在隔离副本中设置 `EVCS_PROJECT_ROOT=/nonexistent` 并重建清单：50项原始 `source_*` 字段须与冻结清单逐项相同；新增 `lookup_*` 须明确指向本次查找根；50个包内输入哈希、27个冻结分析输出哈希及结果文件哈希保持一致。另将副本中的一个输入改动一字节，校验器须非零退出并定位不匹配项。显式来源校正须先核验冻结manifest SHA和全部50项输入内容，再原子写入锁与manifest。验收只在临时副本完成，不能改写冻结包或原始预测。

本设计针对意外路径覆盖，不把本地来源路径当作访问控制或数据权限证明。项目内锁文件曾把冻结清单的绝对来源字符串预先规范化为相对路径；本轮已按冻结清单逐项恢复原字符串，并把可迁移查找提示分列。外部冻结包本身未改动，数值和冻结输出不变。
