# 论文评阅执行协议2.0

协议ID：`EVCS-THESIS-REVIEW-2.0`。数值量表仍为`EVCS-THESIS-CONTENT-1.0`：12项、原始90分、0.5分步长；合计后乘100/90。权重不变，历史数字不自动转换或恢复。适用对象是专业硕士论文内容模拟评阅，不是期刊选稿，也不预测学校结果。

## 修复的主要问题

旧量表权重固定，但分项锚点过粗；评阅者反复用不同理想标准重新定价；记录校验未核验发布条件。新协议把“数字记录完整”与“本次总分可发布”分开。它不保证分数上涨，只要求同样证据在同样标准下得到可解释的判断。

## 评分锚点与专业硕士语境

按[组件锚点](criterion-anchors-v2.json)逐组件检查，再求12项得分。每个组件说明已满足的条件、缺口、正文位置和已读证据；不能先定总分再反填。组件满分相加仍为原有90分。

- 研究可以贡献新方法、受控经验发现、证据诊断或解决工程问题。新算子、全面击败所有模型、完成现场部署，不是所有硕士论文必须同时达到的标准。
- 代理负荷是声明的研究对象时，应评价其任务定义、方法和证据；只有将结论外推至实测功率或运行收益，才以该主张核查计量和业务证据。
- 可靠的阴性结果可以回答研究问题。结果证据分不按“赢了多少次”给分，创新分也不按结构复杂度给分。
- 理论基础检查概念、公式、单位和假设是否准确；工作量检查实际完成的技术难度与问题解决。没有新场景数据或部署不得在这些项重复计价。
- 统计解释检查如何处理依赖、重复次数、校正与结论范围。已清楚限定的三种子/已查看时期，不能再自动解释成夸大。
- 图表内容错误仍属内容；封面签字、分页、学校格式、1200 PPI和用户暂缓的致谢/成果页单列交付门槛。

## 两种可发布模式

| 模式 | 使用条件 | 必须保留的数值 |
|---|---|---|
| `calibration_pair` 配对校准 | 首次启用2.0，或出现必须纠正旧评分的实质发现 | 历史旧分、同标准重评旧稿分、同标准重评当前稿分 |
| `paired_revision` 配对修订 | 已有2.0校准基线且量表/范围相同 | 固定基线组件与得分、当前组件与得分、实际修订差值 |

每项必须满足：**当前分−历史旧分＝评分校准效应＋论文修订效应**。

评分校准效应＝同标准重评旧稿分−历史旧分；论文修订效应＝同标准重评当前稿分−同标准重评旧稿分。新发现若两稿本来都有，应同时评价两稿，不能只扣当前稿并称论文退步。日常模式不重定旧价；需要校准就切换到配对校准。

评价依据没有变化的指标，修订效应固定为0。下调需有新增错误、证据失效、支撑被删除或主张扩大等具体变化。不能把全部指标重标`baseline`规避已有版本。发现旧分偏高时允许订正，但要公开旧评分错在哪里及两稿如何按同一锚点评价。

初次2.0建议核对可恢复的10月16日非实验修订稿与当前稿：`0b30acf6…`和`c9ec6d78…`。这只选定可检查的稿件对，不预设两稿分数。不得把旧76/90或新71/90自动当作正确目标。

## 问题台账与归属

每个问题用稳定ID，记录是否经核实、属于实际缺陷/范围限制/后续拓展、旧稿与当前稿是否存在、严重度、主要归属和证据。未核实疑点可要求检查，不能直接扣分。已查看的负结果应与未核实担忧区别。

同一根因原则上有一个主要评分归属。跨项影响须说明不同要求受何种独立损害并给出证据，例如设计缺少同容量对照与宣称可排除容量解释是两个相关但不同的问题。仅复制“无实测/无新数据/仅三种子”不得在多项累扣。方法上可能出现负预测不等于已证明其造成实质错误；正文SHA变化不等于预测工件失效。

建议归属：现场测量/业务效益主要BR-11；对照匹配与预算主要BR-05；主张支持主要BR-08；统计推断主要BR-09；来源比较主要BR-03；知识增量主要BR-10。归属不替代科学判断，也不是每遇到一项就固定扣若干分。

## 隔离评阅与裁定

正式评分复用本地硕士盲审、完整性和最终证据核验技能。三位AI视角采用同一专业硕士锚点和同一对稿件，分别侧重技术、原创性、可读性；每个视角都评12项相同权重。只分发冻结稿、证据、rubric.json、criterion-anchors-v2.json和reviewer-instructions-v2.md，不分发本协议的治理历史、含历史分数的项目评分README、history或前次报告。

上下文隔离与历史分数盲化分别记录。每位评阅者保存原始文本报告和机器可读分项记录；总分由代码汇总，声明总分与分项和不符就暂缓发布。三份报告不等于三个现实专家，分数范围也不是置信区间。

主评独立核查发现，不机械平均。单项分歧超过该项满分20%，或主评裁定超出三份意见范围，必须解释依据。更严厉的视角不能自动替换跟踪基线。一次独立快照可以保留建议，但不能绕过配对程序改变当前正式分数。

## 日常修订与最终发布

日常修订先检查正文差异和问题台账，只更新“已解决/部分解决/未解决/新发现”；无需每次重读全篇并启动三路评分。只有要求发布新正式总分时，才完成同对材料的三视角、法证核查与配对记录。这样减少无效复评，也保留对真实退步的检查。

正式评分组包前运行[评分准备与缓存索引](review-preparation.md)，核对稿件和证据哈希、阅读范围、主张映射及确定性检查状态。章节或证据变化后按索引重读；未映射变化、未登记证据或政策变化触发全项复核。缓存只复用相同输入闭包的确定性检查结果，不能替代文献阅读、学术判断、三视角完整评阅或法证裁定。

正式发布仍须完成同一材料包的三视角、法证核查与配对记录，并通过评分卡发布验证。缓存命中不证明科学数值正确。图像只按图注纳入内容包；Word/WPS页码、图片实体和全页视觉验收必须单独完成。

数字区间仅作描述，不再仅凭78.89或某个阈值宣布“需较大修订”。修订建议按经核实的当前问题严重度形成：阻断、实质修订、小修、导师审阅。学校等级或优秀评定需要学校标准与实际评审。

## 文件与发布命令

新评阅从`scorecard-template.json`、`issue-ledger-template.json`、`reviewer-record-template.json`建立独立目录。原始报告及历史记录不覆盖。冻结稿、主要证据、评阅报告均记录SHA；URL证据保存可读范围明确的本地摘录快照并记录原链接，校验器不联网，也不推测原文内容。

```sh
python3 scripts/audit_thesis_content_score.py 新评分.json --publish
```

通常的旧命令仍可核验历史记录与算术，但`status: valid`不再代表发布资格。`--publish`另外检查组件加总、基线、前后效应、问题归属、报告文件和哈希、三个评阅者的分项算术。未满足时输出`withheld`并隐藏可发布总分。程序不能验证证据是否被真正读懂、问题严重度是否合理或学术判断是否正确。
