# 当前稿独立评阅说明

此模式只回答“冻结的当前稿在固定量表下达到什么水平”。它不评估相对旧稿的修订增量，也不产生可直接发布的正式配对分数。

## 评阅材料

只阅读本包内的 `manuscripts/current.md`、登记证据、`rubric.json`、`anchors.json` 和本说明。不要访问项目仓库、此前的会话、评分历史、旧稿、评分卡、发布状态或既往评阅报告。若收到的包中出现此处以外的材料，停止评分并报告。

该模式下的准备脚本在读取历史基线或运行原配置中的检查项之前分流。它只读取当前稿、登记证据、当前量表与锚点，并将本说明复制到冻结包。历史评分和既往评阅不会被复制。冻结前，调用者必须逐份检查登记证据正文，确认没有夹带历史分数或旧评阅结论，并提供核查者ID和含时区的ISO 8601时间。未确认时仍可生成preflight记录，但状态为阻断，无法冻结评阅包。标记为 `reviewer_safe` 不是内容自动正确的证明。

示例：

```bash
python3 scripts/prepare_thesis_review.py \
  --project . \
  --config path/to/independent-review-config.json \
  --out docs/thesis/review-preparation-日期/independent-run序号 \
  --review-mode independent_current \
  --confirm-history-screen \
  --history-screen-reviewer-id '核查者标识' \
  --history-screen-reviewed-at 2026-10-27T14:30:00+08:00 \
  --freeze
```

确认值、核查者ID和时间会写入preflight与冻结包manifest。包生成器只能核对登记路径和JSON评分卡结构；它不能替调用者检查科学证据正文，所以这项人工文本核查不得由配置默认值代替。manifest中的实际评阅上下文ID在评阅后填写，准备时保持空值。

## 评分方法

使用 `EVCS-THESIS-CONTENT-1.0` 的12项权重、90分原始满分和0.5分步长。先按锚点逐项评价，再由程序汇总。不得根据期望分数、以往结果或“应该涨分”的预期调整单项。每项写明正文位置、实际阅读的证据、达到的锚点、主要缺口和理由。证据不足标为 `N/A`，不得折算成零分，也不得给出完整总分。

评价范围限于论文实际主张及专业硕士语境。区分已核实缺陷、作者已说明的范围限制、未核实疑点和后续拓展。未核实疑点只提出核查建议。一个问题原则上归入一个主要指标；跨项影响必须说明各自受损的不同要求及证据。不得因缺少实测数据、现场部署或新网络算子，在多个指标重复扣分。

技术、原创性与可读性等评阅角色可以有不同关注重点，但必须使用同一份冻结包、同一量表和相同的12项要求。每位评阅者不得读取其他人的报告。评阅报告须记录实际评阅上下文ID，并明确回答历史分数是否暴露；不能确认时填写“未知”，不得推定为“未暴露”。

## 结果用途

本次独立结果用于描述当前稿，不与历史总分直接相减，也不据此宣称本轮修订提升或退步。正式分数仍须按项目配对校准或配对修订协议，由主评完成证据核实、分歧裁定和 `audit_thesis_content_score.py --publish` 发布检查。准备脚本的就绪状态只表示材料包满足准备条件，不代表论文通过盲审或评分可发布。

图像实体、Word/WPS排版、目录页码和PDF全页视觉验收属于交付检查；本包仅覆盖文本和明确登记的证据。未检查页面不得记作通过。
