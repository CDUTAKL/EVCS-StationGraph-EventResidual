## 1. 目的与证据边界

本补验针对SG-EXP-028中的一个替代解释：JPL共享门控配置的seed-2024在60轮上限处停止（最佳59轮、停止60轮），因此“节点级门控相对同参数共享门控整体MAE低2.71%”可能部分来自共享门控的优化预算不足。补验以相同数据、输入、切分、初始化、优化器和选模规则，比较节点级门控与共享门控在延长预算下的表现。

补验复用已查看的JPL固定测试期，只回答“当前结论是否对训练预算策略敏感”。它不是盲测、独立时间外验证、跨场站确认或未来时期检验，也不能支持实测功率效度、现场运行收益或跨数据家族泛化。若共享门控在延长预算后缩小差距，应相应收窄节点门控增量结论；若差距保留，也只提高当前协议和预算范围内的稳健性证据。

## 2. 为什么是“共同预算策略敏感性”

计划把训练上限由60轮提高到120轮，同时把早停耐心由8轮提高到16轮。两项改动共同构成一次预算策略变化，因此结果只能解释为**共同预算策略敏感性**，不能归因为单独的轮数上限效应，也不能把差异拆分为“轮数效应”和“耐心效应”。若要单独识别某一项，需要另设只改变一个因素的对照；本补验不承担该识别任务。

## 3. 配置、种子与公平性控制

| 项目 | 节点级门控 | 共享门控 |
|---|---|---|
| 配置名 | `mrg_full` | `mrg_shared_gate` |
| 门控方式 | 每个节点保留独立门值 | 门值在节点维度取均值后共享 |
| 可训练参数 | 32,714 | 32,714 |
| 种子 | 2024/2025/2026 | 2024/2025/2026 |
| 训练起点 | 从头训练 | 从头训练 |

共6次正式运行。公平性控制如下：

1. **同种子成对初始化**：同一种子下两配置的初始参数SHA-256必须一致；共享门控复用完整模型已初始化的关系变换、门控和归一化模块，不额外抽取随机数。
2. **容量一致**：两配置均为32,714个可训练参数，容量差为0；不得用参数量差异解释结果。
3. **输入与批次一致**：两配置使用同一JPL冻结张量、同一7通道输入、96片历史、4片目标、同一split起点和同一批次顺序。
4. **调参与选模一致**：两配置均以完整调参集原单位MAE选模，校准段和测试段不参与早停、选模、配置筛选或种子选择。
5. **只改变门控汇聚**：除前向中节点维度的门控汇聚方式外，不改变关系图、损失、优化器、学习率、权重衰减、batch size或梯度裁剪。

## 5. 训练、停止与失败保留

- 优化器AdamW，学习率0.001，权重衰减0.0001，batch size 256，标准化L1损失，梯度裁剪5.0。
- FP32确定性计算，关闭TF32；`num_workers=0`，`threads=2`。
- 最多120轮；连续16轮调参集原单位MAE无改善即早停；最佳检查点按完整调参集原单位MAE选择。
- 任一运行在120轮停止或最佳轮为120时，标记`budget_censored`并保留；不得因触顶而删除该运行。
- 所有运行、失败和中断均保留；不得按测试结果重跑、删除或替换配置。恢复训练只允许在合同完全一致时使用`--resume`。
- 不设基于测试结果的提前停止或方向性停止规则。

## 6. 评价与统计

**主要比较**：同一`(origin, horizon, node)`测试键上，共享门控绝对误差减节点级门控绝对误差；正值表示节点级门控误差更低。报告逐种子方向、三种子均值及样本标准差，并按固定JPL测试期的连续七日块做10,000次配对bootstrap，给出95%区间。

**次要评价**：非零目标MAE（`target != 0`）、事件MAE（`target_event == 1`）、零目标MAE（`target == 0`）、RMSE、逐目标片MAE和逐节点MAE。次要指标只作探索性描述，不因某一分层方向有利而追加确认性主张；不作多重校正后的显著性声明。

**报告要求**：同时给出全局、非零目标和事件组结果；若全局改善但非零或事件组未改善，必须如实并列报告，不能用一个总体指标替代分层结论。所有分层均使用同一冻结测试键，不重新选样。

## 7. 现有入口能否直接支持JPL

结论：**不能直接支持**。现有入口可复用组件，但不能端到端完成本次2配置×3种子的JPL门控补验。

| 现有入口/组件 | 可复用部分 | 不能直接支持的部分 |
|---|---|---|
| `scripts/gate_control_experiment.py` | 两配置名称、配对运行框架、summary核验 | 固定使用Caltech `FrozenData`、`DATA_SHA256`、`SG-DATA-006`协议和`data/eventtime/dataset.npz`，无JPL数据路径或协议切换 |
| `scripts/jpl_relation_controls.py` | JPL数据加载、作用域工厂注入、合同检查和checkpoint锁 | 只构造`full`及三种关系替换，不构造`mrg_shared_gate`，无两门控配置配对路径 |
| `src/evcs_station_graph/jpl_eventtime/data.py` | `FrozenJPLData`及JPL张量校验 | 只提供数据加载，不含训练入口或门控配置 |
| `src/evcs_station_graph/eventtime/gate_control.py` | `SharedNodeGate`共享门控实现 | 需要由新入口注入到JPL runner；旧入口未接线 |
| `src/evcs_station_graph/eventtime/runner.py` | 训练、选模、导出和合同哈希 | 默认配置为Caltech协议；`metric_report`未直接输出非零目标MAE；无bootstrap统计；`code_digest`未覆盖JPL加载器 |

因此，本计划**不宣称ready_to_run**。以下为实现清单，完成并冻结后才可进入运行阶段。

## 10. 结论权限

本补验最多支持：“在JPL固定已查看测试期、当前协议和共同预算策略下，节点级门控与共享门控的整体MAE差异是否仍然存在及其方向。”它不支持：

- 单独轮数上限效应或单独耐心效应的因果识别；
- 盲测、独立时间外验证、未来时期或跨场站泛化；
- 实测功率效度、事件检测性能、现场运行收益或经济收益；
- 对SG-EXP-028、SG-EXP-031、SG-EXP-032既有数值或结论的替换。
